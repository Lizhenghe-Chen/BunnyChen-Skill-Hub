# 代码质量准则

无论修改或新增代码，都必须遵守以下标准（用户多次强调的硬性要求）：

## 1. 简洁高效
- 不做多余的事，避免过度设计；用最简洁的方式实现需求。
- 删除无用代码、死代码、无效参数和冗余分支。
- 代码行数精简，但不得以牺牲可读性为代价。

## 2. 鲁棒（健壮）
- 处理边界情况和异常输入，必要时使用 try/catch 防护。
- 对关键路径做校验与错误处理，避免程序崩溃或产生脏数据。

## 3. 易于维护
- 结构清晰、命名准确、职责单一；公共逻辑提取复用，避免重复代码。
- 可读性优先：代码应让后来的开发者（或 Agent）能快速理解定位。
- 保持代码与文档、注释同步；迭代、优化、修改时同步更新对应文档。

## 4. 不破坏已有功能
- 改动前先理解现有功能与架构，保持向后兼容。
- 涉及重构时，必须验证原有功能仍正常，不因清理而引入回归。

## 5. 主动审查
- 完成改动后主动检查是否有冗余、可复用、可简化之处。
- 保持工作区整洁规范（配置文件、脚本、文档归类清晰）。

## 示例对照
- ✅ 优先：提取公共函数复用，删除重复片段，处理空值与异常。
- ❌ 避免：复制粘贴大段代码、保留无用的导入/变量/死分支、忽视边界情况。
