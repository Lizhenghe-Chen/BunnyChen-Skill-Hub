# Code Quality（代码质量审查与优化）

对代码执行质量审查与主动优化（用户反复强调的硬性要求）：简洁高效、鲁棒健壮、易于维护，且**不破坏已有功能**。

## 工作流

### 1. 先理解，后动手
- 一句话概括这段代码做什么；输入的坑（空值、越界、异常格式）；改动影响哪些上下游
- 看不懂的代码只标记、不删除

### 2. 审查（每个发现先自我质疑）
每个发现先问自己：这是真问题还是风格差异？修复收益是否大于改动风险？有没有更小的改法？
- **简洁**：死代码、无用变量/导入、冗余分支、重复逻辑、过度设计
- **鲁棒**：空值/越界/异常输入/并发；安全风险（注入、硬编码敏感信息）按需加固，不过度防御
- **可维护**：命名准确、职责单一、提取公共逻辑、依赖清晰
- **可读**：魔法数字、嵌套过深、注释与代码不一致

### 3. 优化 + 验证
- **小步改**：一次只处理一类问题；保留原逻辑，每步可回滚对比
- **必验证**：
  - 有测试？全部跑绿再继续
  - 没测试？手动走关键路径，确认输入→输出不变
  - 改了边界处理？用空值/异常值实测
- 涉及对外行为/接口变化时，同步更新注释或文档

## 输出
逐处改动清单，每项一行：`[文件:行] 问题 → 处理方式 → 验证结果`；最后汇总验证结果。

## 红线（绝对不做）
- ❌ 不删看不懂的代码
- ❌ 不改没有测试覆盖的关键路径（先补测试或手动验证）
- ❌ 不为"更优雅"改接口签名、破坏行为兼容
- ❌ 不为小问题引入新依赖

## 示例对照
- ✅ 提取公共函数复用、删除重复片段、补空值与异常处理、每项改动附验证结果
- ❌ 复制粘贴大段代码、保留无用导入/变量/死分支、忽视边界、未经验证就说完成
