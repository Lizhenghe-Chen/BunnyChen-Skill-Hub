# Code Quality（代码质量审查与优化）

对代码执行质量审查与主动优化，遵循以下标准（用户反复强调的硬性要求）。

## 何时使用
- 用户说「检查/整理/优化代码」「保持简洁高效」「去除冗余/死代码」「重构」「提高可维护性」
- 提交前清理、模块重构、代码审查

## 工作流

1. **理解现有功能**
   先阅读目标代码与相关架构，明确功能与既有约定，避免误删或破坏。

2. **审查**（逐项对照）
   - **简洁高效**：删除无用代码、死代码、无效参数、冗余分支；避免过度设计
   - **鲁棒**：检查边界情况与异常输入，必要时加 try/catch 防护，避免崩溃或脏数据
   - **可维护**：结构清晰、命名准确、职责单一；公共逻辑提取复用，消除重复
   - **可读性**：代码应让后来的开发者（或 Agent）能快速理解定位

3. **优化**
   按「不破坏已有功能」原则重构；保留配置、接口与行为兼容；删除冗余但保留必要配置。

4. **验证**
   改动后必须验证原有功能仍正常（运行测试或关键路径），确认不引入回归。

5. **同步文档**
   若涉及对外行为/接口变化，同步更新注释或对应文档。

## 输出
- 逐处改动清单：位置 → 问题 → 处理方式
- 汇总：清理的冗余、复用的公共逻辑、验证结果

## 示例对照
- ✅ 优先：提取公共函数复用、删除重复片段、处理空值与异常
- ❌ 避免：复制粘贴大段代码、保留无用导入/变量/死分支、忽视边界情况
