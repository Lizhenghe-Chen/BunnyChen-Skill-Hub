# 已有项目改造协议

> 来源：redesign-skill + taste-skill §11。改造 = 升级，不是重写。误判模式是改造失败的最大来源。

## 第一步：判模式
- **绿地**：全新做 → 直接走主工作流
- **保留式**：品牌/IA 不变，视觉现代化 → 审计后渐进改
- **翻新式**：新视觉 + 旧内容 → 视觉当绿地，内容/IA 保留
歧义时问一次："保留现有品牌还是视觉推倒重来？"

## 第二步：审计（改前记录现状）
品牌色/字/圆角、页面结构与导航、现有内容块（哪些在干活、哪些是填充）、**要保留的签名模式**、**要退休的 AI 味**、SEO 基线（URL/标题/OG——重设计第一大风险）。

## 第三步：按优先级改（收益/风险比，逐级停手）
1. 换字体——最大视觉提升、最小风险
2. 清配色——去撞色/过饱和，统一中性族（冷或暖）
3. hover / active / focus 状态——让界面活起来
4. 布局间距——max-width 容器、统一 padding、grid 化
5. 换掉陈词组件——三等分卡、转圈、3 塔定价、FAQ 手风琴、4 列页脚链接农场
6. 补 loading / 空 / 错误三态——让界面像成品
7. 排版细节收尾——tabular-nums、text-wrap、光学对齐（图标/按钮内文字 ±1-2px）

## 保底（绝不静默改）
URL 结构、主导航文案、表单字段名/顺序、品牌 logo、法律/同意文案——未经用户确认不动。
不破坏已有功能，每步可验证；依赖先查 package.json；项目用 Tailwind 先确认 v3/v4；已有框架/样式方案不迁移。
